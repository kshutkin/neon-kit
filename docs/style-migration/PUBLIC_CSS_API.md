# Public CSS policy for `@neon-kit/theme-vanilla`

Status: accepted naming and markup policy, 2026-10-07. The build strategy is
validated in migration step 2; these classes are not emitted yet.

## Ownership and names

`theme-vanilla` owns the hand-authored HTML API. Shared theme CSS Modules own
visual rules; their local names and renderer-generated hashes are internal.
Use the repo's existing component, element, and modifier naming conventions.
Possible collisions with consumer CSS are accepted; no package prefix is
required:

- Root or standalone helper: `btn`, `input`, `menu`, or `panel`.
- Named element: `<component>__<element>`, such as `menu__item`.
- Modifier: use the existing family spelling, such as `btn cta`,
  `nav -vertical`, or `nav__item -active`.

Modifiers are used with their documented base class and selected in that
context, rather than as blanket global state rules. Keeping these spellings
is a naming choice, not a requirement to preserve every old selector or
markup contract. Preserve native and ARIA state selectors (`:disabled`,
`:checked`, `:focus-visible`, `[open]`, `[aria-selected]`, `[aria-invalid]`,
and related attributes) where they already describe the actual state.
Do not replace semantic state attributes with visual classes.

## Catalogue mapping

The source inventory in [baseline/inventory.json](baseline/inventory.json)
contains the complete existing selectors, including nested state selectors.
Use these names for their documented markup roles:

| Existing family | Public roots/helpers | Descendants and modifiers |
| --- | --- | --- |
| Button | `btn` | `quiet`, `large`, `cta`, `left`, `right` |
| Link | `link` | Native link state selectors |
| Dialog | `dialog` | `dialog__*`; `-small`, `-large`, `-xlarge` |
| Details | `details` | `details__*`; native `[open]` and disabled/inert states |
| Menu | `menu` | `menu__*`; `-block-start`, `-inline-start`, `-inline-end`; block-end is default |
| Navigation | `nav` | `nav__item`; root `-vertical`, `-tabs`, `-segmented`; item `-active` |
| Keyboard | `kbd`, `kbd-keys` | `kbd-keys__sep` |
| Badge | `badge` | `badge__dot`; `-primary`, `-success`, `-warning`, `-error`, `-info` |
| Tag | `tag`, `tag-list` | `tag__remove`; same semantic root modifiers as badge |
| Table | `table` | `-striped`; semantic table elements and sortable-state attributes |
| Forms | `input`, `checkbox`, `radio`, `fieldset`, `field`, `field-stack`, `field-label`, `field-hint`, `field-error`, `input-group`, `input-affix` | Existing structural and native/ARIA state selectors |
| Combobox | `combobox` | `combobox__*`; root `-multi`; option `-active` |
| Datepicker | `datepicker` | `datepicker__*`; grid `-days`, `-months`, `-years`; cell `-today`, `-selected`, `-muted`, `-in-range`, `-range-start`, `-range-end`, `-range-pending` |
| Timepicker / combined date-time | `timepicker`, `datetime-picker` | `timepicker__*`, `datepicker__panel`; `datepicker -with-time`; shared combobox option classes retain their combobox stem |
| Tooltip | `tooltip` | `tooltip__*`; `-top`, `-right`, `-bottom`, `-left` |
| Shared Neon helpers/effects | `panel`, `disabled-control`, `disabled-surface`, `focus-ring-swap`, `quiet-control`, `interactive-row`, `metal-tinted`, `text-neon`, `shadow-neon`, `inset-shadow-neon`, `border-neon`, `glow-neon`, `foil`, `border-foil` | Preserve the visual/state rules; replace Tailwind-dependent color plumbing with ordinary CSS during translation |

`__*` means the existing element suffixes inventoried for that family, not a
CSS wildcard or an automatically public export of every module class. Shared
element styles keep their owning family's stem when another component uses
them. The vanilla build must detect conflicting public selector mappings
within its own catalogue. Reuse of a modifier name in different component
contexts is intentional; collisions with consumer CSS are accepted.

```html
<button class="btn cta">Save</button>
<ul class="nav -vertical">
  <li><a class="nav__item -active" href="/">Home</a></li>
</ul>
```

## CSS Modules and documentation isolation

An exported CSS Modules class is still local by default. Exporting its class
string to component JavaScript does not preserve the authored selector name
in emitted CSS. Vite and `style-build` generate the corresponding names for
their respective renderer paths. Explicit `:global(...)` selectors bypass
this scoping and must be deliberate. Public vanilla classes are generated by
the separate vanilla build from the shared sources.

Documentation pages showcasing vanilla load its plain CSS separately from
pages showcasing CSS Modules components. Do not load the vanilla catalogue
globally into the shared documentation shell or a component showcase. Use
separate documents or equivalent document isolation when routing alone would
leave previously loaded styles active. This keeps examples representative of
each consumption path. Module class generation provides normal component
scoping; no public naming prefix is needed to distinguish the examples.

## Composition and output

A public base class must include its source export's full visual dependency
closure. A documented base-plus-modifier combination must include the
modifier's closure as well. Consumers never need to discover or write hidden
composed hashes. The vanilla build must handle pseudo/state selectors,
descendant relationships, keyframes, and shared dependencies consistently;
merely renaming the last class of a composed export is insufficient.

Step 2 proves the emitter against that contract. It may use a compilation
naming policy or generated public selectors; that implementation choice does
not change the public names or force renderer modules into the public naming
scheme. Visual declarations are shared sources, not a second manually
maintained stylesheet catalogue.

The planned CSS entries are `index.css`, `theme.css`, `reset-normalize.css`,
`components.css`, and a small set of component-group subpaths. All components
and helpers are included regardless of whether they appeared in Tailwind's
content scan. Selective outputs include their required composed rules and
local defaults. Document reset and root scheme opt-in are explicit choices
outside the aggregate entry. Entry grouping and cascade/overlap policy are
validated with the emitter in step 2.

Generic Tailwind utilities (spacing, grids, display, palette utilities, and
their variants) are outside this public catalogue. Documentation layout moves
to site-owned CSS. Font loading remains a document responsibility. CSS class
names do not define web-component slot or parts APIs.
