Tooltip

The .tooltip component is a styled wrapper around the native popover attribute. Because the browser puts every open popover into the top layer, tooltips always paint above siblings — no z-index juggling, no portals, and no breakage from overflow: hidden, transform, or filter on ancestors.

Placement uses CSS anchor positioning. The trigger that invokes the popover via popovertarget becomes its implicit anchor, so the position tracks the trigger automatically as layout reflows or scrolls.

Basic — Click / Keyboard

Native popovertarget handles activation for free: click, Space, and ⏎ all toggle the popover. Click outside or press ⎋ to dismiss.

Hover & Focus

Add data-tooltip-hover to any trigger to open its popover on hover and on keyboard focus. Open is delayed slightly so casual flyovers don't flash. The tooltip itself keeps the popover open while the pointer is over it, so rich content (links, buttons, copy fields) stays reachable.

Rich Content

Because the popover is a regular block container while open, the body can hold any markup: a title with secondary copy, keyboard hints, badges, even interactive elements. Use the optional .tooltip__title, .tooltip__body, and .tooltip__meta helpers, or compose with Tailwind utilities.

Accessibility

  • For description-style tooltips, use role="tooltip" on the popover and aria-describedby="tip-id" on the trigger.
  • For richer popovers (titles, multiple paragraphs, actions), drop role="tooltip" and rely on the popover's own semantics plus a heading inside.
  • Keyboard users get tooltips on focus when data-tooltip-hover is set; without it, the trigger still toggles the popover via Space / ⏎.
  • ⎋ dismisses any open popover — browser default behavior.
