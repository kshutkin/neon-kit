Tooltip

The .tooltip component is a styled wrapper around the native popover attribute. Because the browser puts every open popover into the top layer, tooltips always paint above siblings — no z-index juggling, no portals, and no breakage from overflow: hidden, transform, or filter on ancestors.

Placement uses CSS anchor positioning. A trigger that invokes the popover with interestfor, commandfor, or popovertarget becomes its anchor, so the position tracks the trigger automatically as layout reflows or scrolls.

Copy-Paste Snippets

Use interestfor for delayed hover and focus hints. Use commandfor for immediate click, Space, and Enter activation. These native invokers are intentionally limited to native interactive elements; use the Web Component or JSX Tooltip when you need arbitrary trigger elements.

Hover & Focus Interest

Native interestfor opens popover="hint" tooltips on hover, keyboard focus, and long-press where the platform supports it. The CSS defaults wait 400ms to open and 500ms to close, and can be overridden per trigger.

Rich Content

Because the popover is a regular block container while open, the body can hold any markup: a title with secondary copy, keyboard hints, badges, even interactive elements. Use popover="hint" for transient help and regular popover for command-opened action content.

Choosing an API

  • For description-style tooltips, use role="tooltip" on the popover and aria-describedby="tip-id" on the trigger.
  • For hover and focus help, use interestfor with popover="hint". The CSS component defines --tooltip-open-delay and --tooltip-close-delay on the invoker.
  • For click-open action content, use commandfor with command="toggle-popover" and a regular popover.
  • Native invokers keep the CSS component JavaScript-free but only work on supported native interactive elements. The Web Component and JSX Tooltip keep the previous broader trigger model at the cost of a small JavaScript controller.
  • ⎋ dismisses open popovers through browser default behavior.
