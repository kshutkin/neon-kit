Menu — Web Component

<neon-menu> is a Light-DOM custom element that adds keyboard behavior to the theme's menu markup: a roving tabindex across <neon-menu-item> rows, arrow-key navigation, Home / End jump, and activation with Enter / Space. Disabled items ([disabled] or aria-disabled="true") remain focusable but cannot be activated. See the rendering-mode ADR.

Installation

pnpm add @neon-kit/theme @neon-kit/web-components

// In your bundle entry:
import '@neon-kit/theme/index.css';
import '@neon-kit/web-components/menu';

Popover-anchored menu

Pair the host element with the native popover API: popovertarget on a trigger button, popover on the <neon-menu>. Open the menu and use the arrow keys, Home, End, Enter, and Space.

Nested popover menus

Nested menus can be composed without extra component code by using a menu item as the native popover trigger for another <neon-menu>. Open the parent, focus Export as, then press →, Enter, or Space to open the child menu. The submenu is authored inside its trigger item so the menu tree shares one root context. Press ← in the child menu to close it and return focus to Export as.

API

<neon-menu> is an autonomous custom element. It does not create any DOM of its own — it consumes the theme's .menu markup and adds keyboard behavior on top. <neon-menu-item> owns item semantics and disabled click suppression.

Markup contract

Rows must be authored as <neon-menu-item class="menu__item"> descendants. Each menu queries its Light-DOM descendants and owns the items whose nearest ancestor <neon-menu> is that menu, so a nested <neon-menu> creates a submenu ownership boundary. The item element does not render its own children, so labels, shortcuts, icons, checkmarks, and chevrons remain consumer-authored markup. Disabled rows use disabled or aria-disabled="true" — both remain in keyboard navigation and click activation is suppressed.

Behavior

  • Provides a default menu role for the host.
  • <neon-menu-item> provides a default menuitem role.
  • Maintains a roving tabindex across items: only the active item has tabindex="0"; the others are -1.
  • On the popover toggle event with newState === "open", focus moves to the first item. The browser's :focus-visible heuristic suppresses the focus ring when the popover was opened by mouse and shows it when opened by keyboard — no manual modality tracking.
  • Queries owned descendant menu items in DOM order and reacts when items are added, removed, or moved.
  • Leaf item activation closes all open popover menus in the same root menu tree after consumer click handlers run.
  • <neon-menu-item> supports popovertarget and popovertargetaction for nested menu composition.
  • A popover menu derives aria-labelledby from its trigger unless the menu already has aria-label or aria-labelledby.

Popover wiring

Pair the host with the popover attribute and a trigger button using popovertarget="<menu-id>" (as in the demo above). Menu items can also use popovertarget to open submenu popovers. For submenus, place the child <neon-menu popover> inside the triggering <neon-menu-item> so the menu tree shares one root context. The theme's .menu CSS provides default placement via position-area: block-end span-inline-end.

Accessibility pattern

Implements the WAI-ARIA Menu and Menubar pattern. The host has a default menu role, each row carries a default menuitem role, and a roving tabindex keeps each menu a single tab stop.

Keyboard support

Key Action
↓ ↑ Move focus to the next / previous item, wrapping at the ends.
Home End Jump to the first / last item.
Enter Space Activate the focused enabled item (calls click()).
→ Open the focused item's submenu and move focus to its first item.
← Close a submenu and return focus to its parent menu item.
Esc Closes the popover (handled by the platform), returning focus to the trigger via the native popover behavior.

Disabled items remain in arrow-key navigation and can receive the roving tabindex, but keyboard and pointer activation are suppressed.

The trigger button keeps its native semantics. On open, focus moves into the menu (first item). On close via Esc or outside dismissal, the native popover behavior returns focus to the trigger.
