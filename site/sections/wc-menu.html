Menu — Web Component

<neon-menu> is a Light-DOM custom element that adds keyboard behavior to the theme's .menu markup: a roving tabindex across .menu__item rows, arrow-key navigation, Home / End jump, and type-ahead. Disabled items ([disabled] or aria-disabled="true") are skipped. See the rendering-mode ADR.

Installation

pnpm add @neon-kit/theme @neon-kit/web-components

// In your bundle entry:
import '@neon-kit/theme/index.css';
import '@neon-kit/web-components/menu';

Popover-anchored menu

Pair the host element with the native popover API: popovertarget on a trigger button, popover on the <neon-menu>. Open the menu and use the arrow keys, Home, End, or type the first letters of an item label to focus it.

Recent

API

<neon-menu> is an autonomous custom element. It does not create any DOM of its own — it consumes the theme's .menu markup and adds keyboard behavior on top.

Markup contract

Descendant rows must use class="menu__item". Disabled rows use the native disabled attribute (on form controls) or aria-disabled="true" — both are skipped during keyboard navigation, click is suppressed, and they are excluded from the roving tabindex.

Behavior

  • Sets role="menu" on the host (unless one is already set).
  • Sets role="menuitem" on each .menu__item (unless one is already set).
  • Maintains a roving tabindex across items: only the active item has tabindex="0"; the others are -1.
  • On the popover toggle event with newState === "open", focus moves to the first focusable item. The browser's :focus-visible heuristic suppresses the focus ring when the popover was opened by mouse and shows it when opened by keyboard — no manual modality tracking.
  • Watches the subtree (MutationObserver) so dynamically added/removed items and disabled/aria-disabled changes stay in sync.

Properties

Property Type Description
items HTMLElement[] All .menu__item rows in DOM order, including disabled ones.
focusableItems HTMLElement[] Items excluding disabled ones, in DOM order.
activeItem HTMLElement | undefined The currently focused item, if any.

Popover wiring

No popover wiring lives in the component itself. Pair the host with the popover attribute and a trigger button using popovertarget="<menu-id>" (as in the demo above). The theme's .menu CSS provides default placement via position-area: block-end span-inline-end.

Accessibility pattern

Implements the WAI-ARIA Menu pattern. The host carries role="menu", each row carries role="menuitem", and a roving tabindex keeps the menu a single tab stop.

Keyboard support

Key Action
↓ ↑ Move focus to the next / previous focusable item, wrapping at the ends.
Home End Jump to the first / last focusable item.
Enter Space Activate the focused item (calls click()).
Printable characters Type-ahead: case-insensitive prefix match against item labels within ~500 ms. From a no-focus state the match starts at the very first item.
Esc Closes the popover (handled by the platform), returning focus to the trigger via the native popover behavior.

Disabled items are kept in the DOM for context but skipped during arrow / type-ahead navigation, do not receive the roving tabindex, and have their click events suppressed.

The trigger button keeps its native semantics. On open, focus moves into the menu (first focusable item). On close via Esc or outside dismissal, the native popover behavior returns focus to the trigger.
