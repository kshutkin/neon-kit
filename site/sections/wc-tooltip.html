Tooltip — Web Component

<neon-tooltip> is an autonomous custom element. Drop it inside the element you want to annotate; it turns its own markup into a popover styled by @neon-kit/theme and wires the parent as the trigger. Renders Light DOM only — see the rendering-mode ADR.

Installation

pnpm add @neon-kit/theme @neon-kit/web-components

// In your bundle entry:
import '@neon-kit/theme/index.css';
import '@neon-kit/web-components/tooltip';

Basic

Plain text inside the element becomes the tooltip body. Default trigger is hover focus; on a <button> parent you also get free click-to-toggle from the platform.

Generated ID

The component generates its own id and points the parent trigger at it with aria-describedby. 

<button aria-describedby="neon-tooltip-k4p9x2m1a">
  Inspect me
  <neon-tooltip id="neon-tooltip-k4p9x2m1a" popover="manual">
    Generated IDs keep this relationship stable.
  </neon-tooltip>
</button>

Placement

Set placement to one of top (default), right, bottom, or left.

Rich content

Use markup for emphasis, icons, and keyboard shortcuts. Do not put interactive elements such as links, buttons, or form controls inside a tooltip.

Non-button parents

Works on any focusable element. Void elements (<input>, <img>) cannot host children — wrap them.

Focus meTooltips work on links too. Focusable span Add tabindex="0" to make a non-focusable element keyboard-reachable.

API

<neon-tooltip> is the popover itself — there is no wrapper DOM. The element it lives inside becomes the trigger.

Attributes

Attribute Values Default Notes
placement top | bottom | left | right top Adds a matching -<placement> class.
trigger Space-separated subset of hover focus click hover focus Set to an empty string (trigger="") to opt out of all automatic triggers and drive the tooltip programmatically.

Popover methods

Method Description
showPopover() Open the tooltip immediately using the native Popover API.
hidePopover() Close the tooltip using the native Popover API.

DOM contract

On connect, the component:

  • Generates an id.
  • Sets popover="manual".
  • Adds the tooltip class plus the placement class (-top, -bottom, -left, -right).
  • Renders a .tooltip__arrow child.
  • Sets a default tooltip role through ElementInternals.
  • Assigns an anchor-name to the parent and references it from the tooltip's position-anchor (existing anchor-name on the parent is reused, not overwritten).
  • Sets aria-describedby on the parent to the tooltip's id — only if the consumer hasn't already set aria-describedby.

Accessibility pattern

Implements the WAI-ARIA tooltip pattern. The tooltip is rendered into the browser's top layer via the native popover API, so it escapes overflow and stacking-context ancestors and stays reachable by assistive technology without ARIA portal hacks.

A default tooltip role is applied through ElementInternals. The tooltip body may include presentational markup such as icons, emphasis, and keyboard shortcuts, but it must not contain interactive controls.

The trigger receives aria-describedby="<tooltip-id>" so screen readers announce the tooltip text alongside the trigger's accessible name. If the consumer already set aria-describedby on the trigger, the component leaves it alone.

For the focus trigger to fire, the parent must be focusable. In development builds the component logs a console.debug hint when the parent is clearly not focusable (e.g. a <span> without tabindex).

Keyboard: Esc closes an open tooltip when pressed from the trigger. Hover and focus close paths also handle dismissal naturally — moving the pointer or focus away closes the tooltip after a short delay. For click-driven tooltips (trigger="click"), clicking the trigger again toggles it closed.
