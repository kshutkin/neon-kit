Sortable headers

Mark a <th> as sortable with aria-sort="none|ascending|descending" and put a <button type="button"> inside it as the click / keyboard target. The button stretches to fill the cell, an arrow indicator renders via ::after (↕ when neutral, ↑ / ↓ when active), and the indicator slot is always reserved so column widths don't shift between states. Sorting logic is up to the consumer — this is presentation + a11y only.

Filter bar

No dedicated component class — a filter bar is just a two-row flex layout composed from existing primitives: <select class="input"> to pick a filter type, <input class="input"> for the value, a default .btn to apply, then a row of .tag chips (with .tag__remove) for applied filters and a .btn.quiet "Clear all" trailing the chips. Consumers wire apply / remove / clear handlers and hide the chips row when no filters are active.

Pagination

No dedicated component class — pagination is composed from existing primitives: .btn.quiet (optionally with .left / .right for grouped edges), a native <select class="input"> for page size, a plain status span, and a flex container that pushes the whole row to the inline-end edge (bottom-right in LTR, bottom-left in RTL).
